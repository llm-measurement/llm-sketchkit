# llm-sketchkit 0.4.0

0.4.0 adds opt-in per-model input, output, cache-read and cache-write token
totals, reported and missing coverage, and a four-bin input-tier histogram to
summary exchange in Go and Python.

Go 1.26 or newer and Python 3.11 or newer remain required.

## What's New

- Track token totals and reported/missing counts for each field, alongside
  invalid/conflicting usage, cache-partition violations and token provenance.
  Missing usage remains distinct from a reported zero.
- Group attempts by input-token tier, separating reported-input coverage from
  jointly complete input/output/cache splits, with token totals and input extrema
  for complete splits.
- Collect, validate and combine model-usage blocks through Go's `modelusage`
  package and Python's `model_usage` module. Leaving `model_usage` unset keeps
  the existing summary shape and base accounting.

See the [integration contract](../../spec/model_usage.md) for APIs, model/byte
budgets and update ordering.

## Limits And Upgrade

Model Usage v1 records aggregates, not raw telemetry or prices. Combination
rejects mixed extension presence and incompatible contracts; applications must
also check their expected contract ID. Use summary combination for cumulative
snapshots rather than adding them as disjoint attempts.

| Component/version | Model Usage v1 |
|---|---|
| sketchkit Go/Python 0.2.3 and 0.3.0 readers | Reject enabled summaries, including enabled-empty blocks |
| sketchkit Go/Python 0.4.0 readers | Support enabled summaries and existing summaries without the extension |
| fleetdiff | Upcoming reader support; version unassigned |
| collector | Upcoming opt-in producer support; version unassigned |

Upgrade all readers before enabling producers at a new observation-window
boundary. Retain capable readers for stored enabled windows: disabling new
emission does not make those windows readable by older readers.

This release updates `golang.org/x/text` from v0.42.0 to v0.43.0 without
changing its normalization implementation. For upgrades from 0.2.x, follow
the [0.3.0 identity migration](../IDENTITY_MIGRATION.md).
