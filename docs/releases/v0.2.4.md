# llm-sketchkit 0.2.4

Release date: 2026-10-16.

Identity-preserving maintenance backport, based on v0.2.3.

## Model Usage

The optional [`model_usage`](../../spec/model_usage.md) extension adds bounded,
per-model token accounting to summary envelopes. Go and Python expose matching
validation, collection, contract identifiers, checked merging, and cumulative
snapshot replacement/replay behavior. Pricing examples are test-only; there is
no production price table or pricing API.

The shared corpus contains 112 named scenarios plus two separate contract
fixtures. Malformed Unicode/JSON, overflow, input-batch bounds, privacy, and
failure atomicity have dedicated regressions. No contract or frozen vector is
changed by this maintenance release.

## Identity Boundary

This line retains v0.2.3 canonicalization, hash domains and framing, sketch
algorithms, and dependencies: Go 1.25.0 minimum, `golang.org/x/text v0.41.0`, and
`google.golang.org/protobuf v1.36.12`. The newer minor line is not substituted.

In particular, `x/text v0.43.0` corrects supplementary-plane recomposition.
Those corrections can change Go `text_v1` bytes and downstream hashes compared
with v0.2.3. For example, `U+11F41 U+0301` yields hex `e1bd85` on this maintenance
line and `f091bd81cc81` with the newer dependency. The legacy behavior is retained
deliberately for identity continuity, not endorsed as corrected normalization.

Go minimum-version selection can select a newer `x/text` through another
dependency. Verify the consumer's resolved module graph and run its identity
fixtures; a direct sketchkit pin alone does not guarantee the older normalizer.
Python retains its historical runtime-dependent normalization and trim behavior.
Preservation means the same runtime and normalization dependency as v0.2.3, not
cross-language equivalence or an implicit migration of existing identities.

## Reader-First Rollout

1. Upgrade readers to an extension-aware release. Use this maintenance line when
   v0.2.3 identity continuity is required. Evaluate a newer minor line separately
   when an identity migration is acceptable.
2. Confirm legacy summaries still round-trip byte-for-byte and enabled summaries
   pass validation. v0.2.3 and older readers reject enabled `model_usage`, including
   an empty block. A reader must not silently discard enabled accounting.
3. Enable producer output only after downstream readers are upgraded. Absence of
   `model_usage` preserves existing canonical summary bytes and means unavailable
   model accounting, not zero usage.

Existing summary and sketch formats remain unchanged when the extension is
absent. Structural preflight now rejects malformed JSON constants, invalid UTF-8,
and unpaired surrogate escapes consistently with full parsing. These malformed
inputs are not part of the preserved valid-wire contract.

## Maintenance Release

Release from the v0.2.3-based maintenance branch with package version `0.2.4` and
tag `v0.2.4`; do not merge this branch into main. Main already has the extension
and its own normalization contract. Publication, signing, and consumer pinning
are separate release operations.
